• Yes, the working tree is:

  /Users/adamwulf/Developer/bun/itsybitsy/.ittybitty/agents/codex-git-commit/repo

  But because it is a Git worktree, its .git is not a directory. It is a pointer file:

  gitdir: /Users/adamwulf/Developer/bun/itsybitsy/.git/worktrees/repo

  So Git stores this worktree’s private metadata there: index, HEAD, locks, refs/worktree
  state, etc. When git commit runs, it must lock and update that worktree-specific index,
  hence:

  /Users/adamwulf/Developer/bun/itsybitsy/.git/worktrees/repo/index.lock

  What you’re missing is that the visible agent repo contains files, but Git’s writable control
  data lives under the main repo’s .git/worktrees/<worktree-name>/. For Codex sandboxing,
  allowing writes to the worktree directory alone is not enough; committing also requires write
  access to the resolved git rev-parse --git-dir path.

  because --add-dir is the CLI flag specifically documented in our notes as “extra writable
  dirs”.

  For git worktrees, I would not add only:

  /Users/adamwulf/Developer/bun/itsybitsy/.git/worktrees/repo

  An actual commit may also need the common git dir:

  /Users/adamwulf/Developer/bun/itsybitsy/.git

  because objects, refs, reflogs, and packed-ref locks can live there. git rev-parse --git-dir
  gives the worktree metadata dir, while git rev-parse --git-common-dir gives the shared git
  database.

  Recommended spawn change:

  codex ... -s workspace-write \
    --add-dir "$GIT_DIR" \
    --add-dir "$GIT_COMMON_DIR" \
    ...

  If we really want this as -c, the likely shape is:

  -c 'sandbox_workspace_write.writable_roots=["/Users/adamwulf/Developer/bun/itsybitsy/.git"]'

  whitelist the main repo .git for worktree git operations, and
